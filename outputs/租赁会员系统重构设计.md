# 造梦者次元摄影棚 —— 租赁 + 会员系统重构设计文档

日期：2026-08-06

## 1. 背景与目标

现有系统（造梦者次元摄影棚）已部署在服务器 `1.14.226.124`（NestJS 后端 + Vue3 管理后台 + Vue3 H5）。用户希望参考 GitHub 上的开源项目重构该系统：

- 以 [nest-admin](https://github.com/xinla/nest-admin) 为架构骨架（技术栈与现有一致：NestJS + TypeORM + MySQL + Redis + Vue3 + Element Plus）
- 会员业务参考 [fuint 会员营销系统](https://github.com/fushengqian/fuint) 的功能设计
- 租赁业务按专业租赁流程重新设计

### 核心定位

- **用户端（H5）以租赁系统为主**：场地租赁为核心，器材/服装租赁为次要业务
- **管理后台以会员管理为主**：会员运营功能完整，租赁订单数据看板优先展示场地租赁
- 用户端除租赁外，还提供活动展示与报名

### 本次重构的交付范围

1. 全新后端（NestJS）与全新数据库（全新初始化，不迁移旧数据）
2. 全新管理后台（Vue3 + Element Plus）
3. 全新用户端 H5（Vue3）
4. 部署到现有服务器，访问地址不变

## 2. 系统定位

### 2.1 用户端（H5）—— 租赁商城

按“租赁商城”设计：

- 首页：场地推荐、器材/服装推荐、活动入口
- 场地租赁：场地列表 → 详情 → 选日期/时段 → 下单（含押金）→ 支付 → 到店核销
- 器材/服装租赁：商品列表 → 详情 → 选租期（按天或按时段）→ 下单（含押金）→ 支付 → 领取/归还 → 押金退还
- 活动：活动列表 → 详情 → 报名
- 会员中心：等级、积分、储值余额、次卡、优惠券、订单、邀请码等辅助功能

### 2.2 管理后台 —— 会员运营中心 + 租赁运营台

- **主导航以会员管理为主**：会员档案、等级体系、积分、储值、次卡/套餐、优惠券、签到、生日礼遇、推荐返利、营销活动
- **租赁管理为第二业务区**：场地管理、器材/服装商品管理、租赁订单、核销、归还
- **数据看板优先展示场地租赁数据**：场地订单量、场地收入、会员增长、储值余额等
- 平台支撑：管理员/角色/菜单/权限、评价、反馈、通知、操作日志、系统设置
- **单商户多账户模型**：后台属于一个商户，支持多个后台账户；只有超级管理员能创建新后台账户，并能配置其他账户的角色与权限；普通后台账户只能访问被授予的功能

### 2.3 技术底座

- 后端：NestJS + TypeORM + MySQL 8 + Redis + JWT
- 管理后台：Vue3 + Vite + TypeScript + Element Plus + Pinia
- 用户端：Vue3 + Vite + TypeScript + Pinia
- 权限模型：RBAC（管理员/角色/菜单/权限），参考 nest-admin
- 通用基础设施：统一响应格式、统一异常处理、统一校验、Base 增删改查模板、操作日志、请求日志
- 服务器环境不变：Node 18、MySQL、Redis、Nginx、PM2

## 3. 业务模块

### 3.1 租赁区

#### 场地租赁（核心）

| 模块 | 说明 |
|------|------|
| 场地管理 | 场地信息、图片、地址、价格（工作日/周末/节假日）、说明、上下架 |
| 时间段档期 | 每日可预订时段，管理员可配置；档期冲突自动锁定，防止重复预订 |
| 日历排期 | 管理后台日历视图查看每日场地占用情况 |
| 预订下单 | 选日期 + 时段 → 计算金额 → 提交订单；可叠加优惠券/储值/积分 |
| 订单管理 | 订单状态机：待支付 → 已支付 → 已核销 → 已完成 / 已取消 / 已退款 |
| 押金 | 可配置押金；模拟支付下订单完成后标记为已退还，真实支付启用后原路退回微信/支付宝 |
| 核销 | 到店核销：手机号/订单号验证后核销 |

#### 器材/服装租赁（次要业务）

| 模块 | 说明 |
|------|------|
| 商品管理 | 每件商品可配置：名称、图片、库存数量、计费方式（按天或按时段）、单价、押金额、说明 |
| 租期选择 | 按天租赁选天数；按时段租赁选日期+时段 |
| 库存校验 | 下单时校验库存，防止超租 |
| 归还登记 | 归还时登记状态，无损坏则退还押金，有损坏则按赔偿规则扣款 |
| 续租 | 支持续租（按相同计费规则追加） |

### 3.2 会员区（完整档）

| 模块 | 说明 |
|------|------|
| 会员档案 | 手机号、昵称、头像、标签、注册时间、消费统计 |
| 会员标签 | 管理员手动打标签或按规则自动打标签 |
| 等级体系 | 后台可灵活配置：等级档位、名称、升级条件（按累计消费金额/次数等），消费后自动升级；降级规则可配置，默认不降级 |
| 积分 | 消费得积分、签到得积分、积分抵扣/兑换；流水明细可查 |
| 储值余额 | 充值、消费扣款、退费；余额流水可查 |
| 次卡/套餐 | 购买次卡（含多次使用权），每次核销扣次，剩余次数可查 |
| 优惠券 | 满减券/折扣券；后台发券、活动发券、生日发券；使用记录可查 |
| 推荐返利 | 会员生成邀请码，被邀请人消费后给推荐人返利（按比例/固定金额，可配置） |
| 生日礼遇 | 生日月/生日当天自动发放优惠券或折扣（可配置） |
| 签到 | 每日签到得积分，可配置连续签到奖励 |
| 营销活动 | 活动发布（标题、图片、时间、规则）、H5 展示、用户报名、活动发券 |

### 3.3 平台区

| 模块 | 说明 |
|------|------|
| 管理员/角色/菜单/权限 | RBAC（单商户多账户），参考 nest-admin；超级管理员创建账户、分配角色与菜单权限，其他账户按授权范围访问 |
| 评价 | 用户对场地/商品评价 |
| 反馈 | 用户反馈与后台回复 |
| 通知 | 系统通知（订单状态、会员等级变化等） |
| 操作日志 | 管理员操作审计 |
| 数据看板 | 场地订单量/收入、会员增长、储值余额等统计 |
| 系统设置 | 系统参数、支付开关、业务参数配置 |

## 4. 关键数据流

### 4.1 场地租赁主线

```
浏览场地 → 选日期/时段（锁定档期防冲突） → 提交订单（金额计算 + 优惠叠加）
→ 支付（模拟支付，接口预留真实支付） → 已支付 → 到店核销 → 订单完成
→ 自动累计积分/消费金额 → 自动升级/发放返利
```

### 4.0 会员注册

- 前台会员注册**无需邮箱验证、无需短信验证码**，填写手机号/昵称等基础信息即可注册
- **防批量注册**：
  - 同一 IP 的注册频率限制（如每小时 N 次，阈值后台可配置）
  - 同一设备/浏览器指纹关联账号数量限制
  - 注册接口统一频率限流（Redis）
  - 注册后进入风控观察：批量特征明显的账号（同 IP 多账号、异常设备）标记为风控账号，可在后台人工处理

### 4.2 器材/服装租赁主线

```
浏览商品 → 选租期（按天/按时段） → 库存校验 → 提交订单（含押金）
→ 支付 → 领取 → 归还登记（检查状态） → 无损坏退押金 / 有损坏扣款
→ 订单完成 → 自动累计积分/消费金额
```

### 4.3 会员成长主线

```
消费完成 → 累计消费金额/次数 → 触发等级升级检查 → 发放积分
→ 推荐返利结算 → 通知用户 → 用户可在会员中心查看
```

## 5. 健壮性设计

### 5.1 异常与防错

- 全系统统一响应格式（`{ code, message, data }`）与统一错误提示
- 场地档期防冲突：数据库行锁 + Redis 缓存双重保障，同一时段只允许一位用户预订
- 金额计算统一走定价规则（工作日/周末/节假日价、优惠券抵扣、押金、退费），订单可追溯
- 支付与订单状态变更全部记录操作日志，可查账
- 模拟支付：用户点击支付即成功；真实微信/支付宝接口预留（商户号、回调、退款），后续通过开关启用

### 5.2 测试

- 单元测试：金额计算、优惠叠加、积分/等级规则、押金退还逻辑
- 集成测试：场地预订全流程、器材租赁归还全流程、会员成长全流程（消费→积分→升级→用券）
- 上线前冒烟测试：用户端主要页面、管理后台主要功能、核心 API

## 6. 上线方式

1. 在现有服务器上并行搭建新版本（新代码目录 + 新数据库）
2. 新数据库全新初始化（管理员账号、场地示例、器材示例、会员等级初始档等种子数据）
3. 测试通过后切换 Nginx/PM2 指向新版
4. 旧版停止运行；旧数据无需备份（按用户要求）
5. 访问地址保持不变：H5 `/`、管理后台 `/admin/`、API `/api/`

## 7. 明确不做（YAGNI）

- 不做微信小程序（H5 先行，后端接口按多端共用设计，后续可加小程序前端）
- 不做真实支付对接（预留接口，等商户号到位后开启）
- 不做旧数据迁移
- 不做复杂的供应链/多门店/多仓库存管理
- 不做即时通讯
